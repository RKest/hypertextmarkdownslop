OpenTelemetry GenAI Semantic Conventions · Issue #477 “Agent vs workflow”

Which noun covers both an agent and a workflow?

#477 proposes one span type for invoke_agent and invoke_workflow. This page takes the consensus properties of an agent and of a workflow from 11 sources, finds the nouns those same sources use for things that could be either, extracts each source’s definition of each noun, and scores every noun on how well its definitions carry the agent and workflow properties. Scope: agent + workflow only. Sources fetched 2026-10-23; every property claim is backed by a quote.

Scoring rule (the only criterion)
  1. Property which is shared between <term> and agent is a point * number of docs which outline the property in <term> and mention the term in the first place
  2. Property which is shared between <term> and workflow is a point * number of docs which outline the property in <term> and mention the term in the first place
  3. Property which agent has, which <term> doesn't is minus a point * number of docs which outline the property in <term> and mention the term in the first place
  4. Property which workflow has, which <term> doesn't is minus a point * number of docs which outline the property in <term> and mention the term in the first place
A property in both the agent and the workflow list (P1–P4) counts under rules 1/3 and again under 2/4. agent and workflow themselves are scored as reference rows and can’t win.

3. Overlap

Agent: an identifiable, configured entity built on an LLM that pursues a task or goal autonomously, with the LLM deciding which step to take next, and that uses tools to act on its environment and can delegate to or be composed with other agents.

Workflow: a coordinated process of multiple steps that combines LLM calls or agents (often several agents) with non-LLM tools or code, where the routing between steps may be fixed in code or decided at runtime by an LLM.

Both are LLM-based (P1), use tools or code (P2), compose other agents (P3), and let an LLM pick the next step (P4). So an LLM-routed multi-agent setup (OpenAI Agents SDK handoffs, Microsoft Agent Framework’s Magentic orchestration, a Google ADK coordinator agent, Azure Foundry group chat) fits both definitions.

4. Difference
  • Agent only: a goal or instructions (P5), autonomy (P6), a configured identity (P7). Workflows have a name in 6 of 11 sources, below the consensus bar.
  • Workflow only: multiple steps or nodes (P8). An agent’s loop is a minority feature (4 of 11), so a single agent isn’t a workflow.
  • Same property, different strength: for an agent, the LLM must decide the next step; a workflow merely allows it. “Control flow predefined in code” is asserted by only 4 sources, so it isn’t a workflow property.
  • Hence a deterministic graph is a workflow but not an agent, and a single agent loop is an agent but not a workflow.

Method: each source was read separately with the same instructions. A noun counts as mentioned only when the source uses it for something that is, contains, or is built from agents or workflows, so incidental uses such as “system prompt” or “control flow” don’t count. Each mention records a verbatim definition and, for each of P1–P8, a verbatim quote or nothing. A second, strict pass then kept a ✓ only when its quote is about the noun’s own referent, not about agents in general or a member of it. That pass changed 42 of the grades (40 removed, 2 added); changed grades have an amber ring and the reason in their tooltip. Discovered nouns not scored: pattern, orchestration pattern, framework, platform, project, infrastructure, skill, session tree, agent mesh, ecosystem, network, crew, coordinator. They name a design template, library, host or container, or only one side (agent or workflow). The Gemini Interactions API page could not be fetched (redirect loop).
